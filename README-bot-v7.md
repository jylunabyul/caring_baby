# V7 — 투약·체온 알림 중지 및 낮잠·밤잠 기록

## 적용

V6가 적용된 프로젝트에서 `supabase/daddy_bob_jooseyo_v7.sql` 전체를 실행해 `v7_ready=true`를 확인하세요. 기존 건강·수유·재고·알림 데이터를 초기화하지 않습니다. 전용 수면 테이블과 함수를 추가하며 기존 일괄 처리 함수에 새 동작을 연결합니다.

`n8n/daddy-bob-jooseyo-v7.json`을 가져와 기존 Supabase·Telegram·기본 Google Gemini 자격 증명을 선택합니다. 이전 워크플로우와 스케줄을 중지하고 새 버전 하나만 게시하세요. 본인 개인 chat ID·sender ID 제한과 다른 사용자 거절 회신은 유지합니다.

## “약이랑 체온은 그만 기록해도 돼”

이 표현은 **과거 기록 삭제가 아니라 알림 중지**로 해석합니다. 해당 아이의 체온 반복 알림, 약별 반복 알림, 고정 시각 투약 일정을 중지하고 발송 예약 토큰을 무효화합니다. 이미 전달된 Telegram 메시지는 회수하지 않습니다. 전송 중인 메시지는 중지와 교차해 한 번 더 도착할 수 있습니다.

- “별이 약이랑 체온 알림 그만 보내줘” → 별이의 두 종류 알림 중지.
- “별이 체온 알림만 중지해줘” → 체온만 중지, 투약은 유지.
- “별이 타이레놀 알림 그만” → 해당 이름의 약 알림만 중지.
- “모든 아이 투약·체온 알림 전부 중지” → 본인 소유 아이 전체.

아이 한 명이면 이름을 생략할 수 있습니다. 여러 명이고 대상이 불명확하면 질문합니다. 기존 건강 기록과 수동 입력은 유지하고, 수유·아침 계획 알림은 건드리지 않습니다. 대기 중인 해당 건강 알림 설정 요청도 취소해, 나중에 오래된 확인 버튼을 눌러 다시 켜지는 일을 막습니다. 중지 요청은 직접 처리하고 결과를 회신합니다.

## 낮잠·밤잠 기록

- “별이 낮잠 들었어” → 낮잠 시작 시각 확인 후 저장.
- “별이 밤잠 시작했어” → 밤잠 시작 시각 확인 후 저장.
- “별이 깼어” → 현재 진행 중인 한 수면 기록에 기상 시각 확인 후 저장.
- “별이 어제 오후 1시부터 2시까지 낮잠 잤어” → 지난 수면 구간을 한 번에 확인·저장.
- “별이 어제 밤 10시에 자서 오늘 아침 7시에 깼어” → 날짜를 넘는 밤잠 구간을 기록.
- “별이 수면 기록 보여줘” 또는 `/rest 별이` → 최근 10건, 진행 중 여부와 수면 시간(분).

입력·출력은 한국 시간이며 새 테이블은 시작/종료의 UTC·KST 자동 생성 컬럼과 수면 시간을 함께 보관합니다. 기상 전이면 종료·수면 시간은 null입니다. 한 아이에게 진행 중인 수면은 한 건만 허용하고, 겹치는 구간·미래 실제 시각·출생 전 시각은 거절합니다. 낮잠인지 밤잠인지 불분명하면 임의로 정하지 않습니다.

수면 기록은 수유·투약·체온 알림 시간을 자동 변경하지 않습니다. 건강 알림은 별도 설정을 따릅니다. `/reset`의 수유 기록 초기화는 수면 기록을 지우지 않습니다. 명시적으로 아이 전체를 삭제하면 해당 아이의 수면도 FK로 함께 삭제됩니다.

## 보존·권한·검증

새 수면 테이블은 RLS를 켜고 anon/authenticated 직접 접근을 막습니다. 기존 service_role 전용 RPC와 본인 계정 제한을 유지합니다. 새 수면 동작도 일괄 요청에 포함할 수 있으며, 뒤쪽 요청 실패 시 앞선 수면 입력을 포함해 전체 롤백합니다.

`npm run build:bot && npm run check && npm test`로 알림 범위별 중지·기록 보존·이전 설정 재활성화 방지·진행 수면·지난 수면·자정 횡단·중복/겹침 방지·UTC/KST·RLS·일괄 롤백을 임시 PostgreSQL 호환 DB에서 검증합니다. 실제 Gemini 언어 해석·Telegram 전송은 게시 후 확인해야 합니다.
