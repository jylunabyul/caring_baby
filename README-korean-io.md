# 한국 시간 입력·UTC/KST 동시 저장·한국 시간 출력

V6 적용 상태에서 `supabase/daddy_bob_jooseyo_korean_io.sql`을 실행하고 `n8n/daddy-bob-jooseyo-v6-kst.json`을 가져옵니다. 기존 Supabase·Telegram·Gemini 자격 증명을 선택하고 이전 워크플로우를 중지한 뒤 새 버전만 게시하세요. 과거 기록은 삭제하거나 일괄 9시간 이동하지 않습니다.

- 입력 기준: Asia/Seoul. 오후 1시 = 13:00, 오전 1시 = 01:00. 오전/오후가 불명확한 ‘한 시’는 질문합니다.
- Telegram 메시지 수신 시각을 한국 시간으로 바꿔 ‘오늘·어제·한 시간 전’의 기준으로 사용하도록 모델에 제공합니다.
- 모델은 한국 달력 시각 `YYYY-MM-DDTHH:mm:ss`를 추출하고, 새 Normalize Korean input times 노드가 `+09:00`을 한 번만 붙입니다. 다른 오프셋이나 잘못된 날짜는 추측해 저장하지 않습니다. 기존 +09:00 값은 그대로 유지합니다.
- 원본 timestamptz는 동일한 절대 시각을 저장합니다. fed_at_utc/fed_at_kst, occurred_at_utc/occurred_at_kst 및 알림 계획의 해당 자동 생성 컬럼을 함께 유지합니다. 예: 한국 오후 1시 = UTC 04:00 = KST 13:00.
- 봇 확인·저장 안내에는 한국 시간을 표시합니다. 단일 수유 메시지에 남아 있던 ISO 출력도 수정했습니다. DB 원본 timestamptz를 Supabase가 UTC로 표시하는 것은 저장 시각이 틀렸다는 뜻이 아니며, 한국 시각 확인에는 *_kst를 사용합니다.

테스트는 실제 PostgreSQL 호환 임시 DB에서 한국 13:00 입력의 UTC 04:00/KST 13:00 저장, 기존 데이터 보존, 단일 수유 확인 출력, 중복 시간 변환 방지, 자정·오전/오후 구분을 확인합니다. 실제 Gemini의 자연어 해석은 확인 메시지의 날짜·오전/오후를 보고 승인하세요. 미래의 실제 수유·투약 기록은 거절하고 미래 계획과 구분합니다.
