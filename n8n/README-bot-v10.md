# V10 특수 이벤트 기록

V8 SQL이 적용된 환경에서 V10 JSON으로 교체합니다. 새 SQL이나 테이블은 필요 없습니다. 기존 `daddy_bob_jooseyo_health`의 `kind=note`를 사용하여 기록을 유지하고 타임라인·오후 9시 리포트에 함께 표시합니다.

예시:
- 별이 대변 봤어
- 별이 오늘 오후 1시에 병원에서 감기 진료 받았어
- 별이 아침에 대변 봤고 오후 1시 병원에서 진료 받았어 (모호한 시각은 확인)
- /event 별이 대변을 봄
- 별이 특이사항 보여줘 / 오늘 하루 기록 보여줘

Gemini가 [대변], [병원진료], [예방접종], [구토], [이벤트] 등 설명을 기존 건강 메모로 분류합니다. 여러 사건은 batch로 나누어 한 번 확인 후 저장합니다. 실제 발생한 사건만 기록하고 진단·처방·용량 등 말하지 않은 세부사항은 만들지 않도록 지시합니다. 미래 병원 예약은 실제 진료 기록으로 저장하지 않습니다. 자연어 추출의 실제 응답 품질은 선택한 Gemini 모델에서 확인이 필요합니다.

아이를 생략하면 등록된 아이가 한 명인 경우에만 추론합니다. 날짜·시간 입력과 출력은 한국 시간이며 원래 UTC/KST 저장 구조를 사용합니다. 시간 미지정 시 기존 확인 시각 저장 규칙을 유지합니다.

적용: JSON 가져오기 → 기존 Telegram / Supabase / Google Gemini 자격증명 선택 → 기존 워크플로 게시 해제 → V10 게시. 같은 봇의 활성 Telegram Trigger는 하나만 유지합니다. V9의 매일 오후 9시 리포트도 포함되어 있습니다. 실제 서버에는 자동 적용하지 않았습니다.
