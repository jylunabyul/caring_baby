# V6 — 복합 요청, 처리 결과 회신, 본인 전용 접근

## 적용

V5가 적용된 Supabase에 `supabase/daddy_bob_jooseyo_v6.sql` 전체를 실행합니다. `v6_ready=true`를 확인하세요. 기존 기록을 삭제·초기화하지 않고 고정 투약 시간표 테이블과 전용 함수를 추가합니다. SQL 실행 자체는 실제 기록을 변경하지 않습니다.

`n8n/daddy-bob-jooseyo-v6.json`을 새 워크플로우로 가져와 기존 Supabase·Google Gemini·Telegram 자격 증명을 선택합니다. **새 Reply access denied 노드에도 Telegram 자격 증명**을 연결하세요. 이전 봇·스케줄을 중지하고 V6 하나만 Publish합니다. 사용자 메시지는 새 RPC를 사용하며 수유·아침·분 단위 건강 스케줄은 유지합니다.

## 복합 요청 처리

Gemini가 최대 12개 항목으로 분리하고 각각 수치·이름·기록 ID·시각·필수 값을 검증합니다. `실제 체온 기록+매시간 확인`은 하나의 care_setup으로 묶어 측정 행이 중복되지 않게 합니다. 미래에 약을 먹일 일정은 실제 투약 기록과 구분합니다.

정보가 완전하면 전체 내용을 한 번에 보여주고 확인받습니다. 확인 후 한 DB 트랜잭션에서 처리하며 하나라도 실패하면 **이번 묶음 전체를 롤백**합니다. 기존 기록·일정은 유지합니다. 성공한 요청은 같은 Telegram update_id로 재전달돼도 다시 실행하지 않습니다.

기존 투약 시간표의 동일 아이·약명·시간 슬롯은 upsert합니다. 실제 관찰·수유 기록은 새 사건이면 추가하며 기존 기록 ID를 지정한 수정은 기존 행을 변경합니다. 단순히 같은 양을 먹었다고 예전 기록을 임의로 덮어쓰지 않습니다. 명시적 삭제는 이전처럼 확인 후 수행합니다.

## 빠진 값은 한 번에 확인

예: “별이 현재 10:30 36.9도. 오늘부터 1시간마다 체온 확인. 감기약 점심12~1시, 저녁5~6시,22시에10ml.”

- 체온 36.9℃·실제 시각·간격 **60분**을 보존합니다. 이미 말한 간격을 다시 묻지 않도록 지시합니다.
- `감기약`만으로 특정 약을 추측하지 않고 실제 약명을 확인합니다.
- 12~1시, 5~6시 범위는 시작·끝·중간 시각 중 하나를 임의로 선택하지 않습니다. 정확한 시각을 묻습니다.
- 체온 알림의 야간 포함 여부도 확인합니다.
- 불완전한 요청은 30분짜리 대화 초안으로 저장할 뿐 실제 기록/알림 일부를 먼저 저장하지 않습니다. 후속 답변에서 전체 초안과 최초 측정 시각을 유지하며 보완합니다.
- 확인한 적 없는 투약량·빈도·기간을 모델이 계산하지 않습니다. 사용자 계획의 임상적 적절성을 검증하는 기능은 아닙니다.

## 처리 결과는 답장

- 성공: “아버님, 기록을 업데이트했습니다. (N개 요청 처리)”
- DB에서 전체 롤백이 확인된 실패: “아버님, N번째 요청을 처리하지 못해 이번 묶음의 변경을 모두 되돌렸습니다. 기존 기록은 유지했습니다.”
- HTTP/네트워크 실패로 커밋 여부를 알 수 없는 경우: “저장 여부가 불확실합니다”와 조회 방법을 안내합니다. 복구됐다고 거짓으로 답하거나 무조건 재시도해 중복 저장하지 않습니다.
- 입력 부족: 인식한 항목과 필요한 값만 질문합니다. 감사·일반 대화는 Gemini가 직접 답합니다.
- 중복 요청·변경 없는 요청도 수신 확인을 회신합니다. 과거 V5의 사용자 입력 무응답 처리는 대체합니다.
- **사용자 메시지**에 대한 응답 경로를 보장하도록 구성했습니다. 알림 대상이 없는 정기 실행의 `messages: []`는 정상이며 매분 “없음” 메시지를 보내지 않습니다. Telegram 자체 장애 시 실제 전달을 절대 보장할 수는 없습니다.

## 고정 시각 투약 리마인더

정확한 미래 ISO 시각, 약명, 사용자 지정 용량·단위로 1회 일정을 만듭니다. 매일 반복은 사용자가 명시했을 때만 설정합니다. 종료를 명시하지 않은 반복은 확인 화면에 “중지할 때까지”를 표시합니다. 수유 야간 중지와 별도로 지정된 투약 시각에 안내합니다. 실제 복용 여부는 별도 기록해야 합니다.

기존 1분 건강 스케줄에서 고정 일정도 조회하고 예약 토큰을 발급합니다. 전송 성공 후만 완료 표시하며, 정지·미루기는 예약을 무효화해 오래된 완료 응답이 새 시각을 덮어쓰지 못하게 합니다. 외부 전송과 DB 완료는 분산 트랜잭션이 아니므로 전송 직후 장애에서 중복 가능성이 남습니다.

## 본인만 명령 허용

**개인 chat ID와 sender ID가 모두 `9114513581`이고 private 대화인 경우에만** 기존 Normalize → 모델/DB 흐름으로 갑니다. 다른 개인·그룹 요청은 **“죄송합니다. 허용되지 않았습니다.”**로 회신하고 종료합니다. 후속 Normalize 노드의 기존 개인 계정 검사도 유지합니다. 이는 Telegram에서 받은 이벤트의 식별자를 검사하는 앱 접근 제어입니다.

BotFather는 봇 생성/관리용이며 본인의 chat ID를 조회하는 기능이 아닙니다. 기존 n8n Telegram 수신 데이터의 `message.chat.id`에서 확인한 값입니다. 봇은 다른 사람이 찾아 메시지를 보낼 수 있지만, 그 사용자의 명령은 모델·DB로 전달하지 않습니다.

## 검증

`npm run build:bot && npm run check && npm test`.

임시 PostgreSQL 호환 DB에서 복합 저장·동일 슬롯 upsert·중복 처리·중간 실패 전체 롤백·초안 보존·기존 기록 보존·고정 알림 예약을 검증합니다. 모의 Gemini 결과와 실제 n8n 표현식 파서, 접근 허용/거절 분기, 오류 응답 경로도 검사합니다. 실제 Gemini 언어 해석·API 자격 증명·Telegram 발송은 게시 후 확인해야 합니다.
