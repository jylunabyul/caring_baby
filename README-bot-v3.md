# Daddy Bob Jooseyo V3 — GPT 자연어 입력 및 야간 알림 휴식

## 상태와 변경

- 일반 텍스트·슬래시 명령을 GPT가 구조화된 의도로 해석합니다. 버튼 콜백은 토큰으로 직접 처리합니다.
- GPT 응답은 허용 명령, 등록된 아이, 최근 기록 ID, 수치·시간 형식을 검증한 뒤 DB에 전달합니다. 추측한 값이나 모호한 입력은 질문으로 돌려보냅니다.
- 저장·수정·삭제·성장·아이 추가·재고·수면 설정은 확인 후 변경합니다. 확인 답변은 JSON boolean과 명확한 긍정/부정 문구를 함께 검사하고 DB에서 현재 확인 토큰을 다시 검사합니다. 조건부 답변(“응 그런데 100으로”)은 확정하지 않습니다.
- 아이별 기본 알림 휴식 시간은 **한국 시간 22:00 이상, 08:00 미만**입니다. 수유·재고 자동 알림만 멈추며 야간 수동 기록은 계속 가능합니다. 08시 이후 다음 실행에서 여전히 조건에 해당하면 알립니다. 이것은 아기의 수유 필요 여부를 판단하는 설정이 아닙니다.
- 기존 V2 수유·성장·재고 데이터는 유지합니다. 변경 SQL은 전용 접두사 객체만 수정합니다.

## 적용 파일

- SQL: `supabase/daddy_bob_jooseyo_v3.sql` — V2 적용 후 실행. 기존 설치 SQL을 다시 실행하지 마세요.
- n8n: `n8n/daddy-bob-jooseyo-v3.json` — 새 워크플로우로 가져오거나 기존 워크플로우를 백업한 뒤 교체합니다.
- 기존 Supabase/Telegram 자격 증명을 선택하고 `Get chat context`에도 Supabase 자격 증명을 연결합니다.
- `GPT intent and yes-no`는 HTTP Request 노드로 OpenAI Chat Completions API를 호출합니다. **Predefined Credential Type → OpenAI API** 자격 증명을 선택합니다. `gpt-4.1-mini`, JSON Schema strict 응답을 사용합니다. 키는 n8n Credentials에만 저장합니다. ChatGPT 구독과 별개인 OpenAI API 사용 요금이 발생할 수 있습니다.
- 지정한 n8n에 직접 접근할 때는 환경변수 `n8n_daddy`를 `X-N8N-API-KEY` 헤더에 사용합니다. 키를 출력하거나 JSON에 복사하지 않습니다. Codex 클라우드에서 `n8n-production-3e2d1.up.railway.app` 접근이 허용돼 있어야 합니다. n8n에서 OpenAI로 나가는 연결은 Railway 측 네트워크를 사용합니다.
- SQL과 자격 증명을 준비한 후 이전 워크플로우를 중지하고 V3 하나만 게시합니다. 같은 봇의 Trigger·알림 스케줄을 병행 운영하지 마세요.

## 예시

- “별이 120 먹었어. 150 탔어” → 실제 먹은 양·조유량 확인 → “응” → 저장.
- “아니” → 현재 대기 요청 취소. 대기 요청이 없거나 만료됐으면 변경하지 않습니다.
- “별이 마지막 기록 110으로 바꿔줘” → 최근 기록·기존 조유량을 확인해서 수정 질문. 특정되지 않으면 다시 질문합니다.
- “별이 6.5kg, 키 62cm야” → 성장 기록 확인 → “응” → 저장.
- “별이 밤 10시부터 아침 8시까지 알림 쉬어줘” → 시간 설정 확인 → “응”.
- `/sleep 별이 22:00 08:00`, `/sleep 별이 off`도 지원합니다.
- 여러 아이 중 대상이 명확하지 않으면 GPT가 임의 선택하지 않도록 지시하고, 허용된 이름인지 다시 검증합니다.

## 데이터와 검증 한계

텍스트와 함께 등록된 아이 이름·ID, 최근 최대 20건의 기록(양·시각·ID), 현재 대기 요청의 입력 내용이 OpenAI에 전달됩니다. API 키·Supabase 자격 증명·확인 토큰은 전달하지 않습니다. `store:false`는 Chat Completions 저장 옵션이며 제공자의 모든 보존 정책을 없애는 뜻은 아닙니다. n8n 운영 입출력 이력 저장은 계속 꺼 둡니다.

모델 오류·거부·불완전 JSON·낮은 확신·유효하지 않은 아이/기록·조건부 승인은 DB 변경으로 연결하지 않습니다. 모델 해석은 틀릴 수 있으므로 실제 GPT 호출 예시와 확인 메시지를 운영 적용 전 검증해야 합니다. 최근 컨텍스트에 없는 오래된 기록 ID는 다시 확인하도록 안내합니다. 성장 참고량 등 V2의 의료적 한계는 그대로 유지합니다.

`npm run build:bot && npm run check && npm test`로 생성물·SQL·의도 검증을 검사합니다. 테스트는 임시 PostgreSQL 호환 DB와 모의 GPT 응답을 사용하며 실제 OpenAI·n8n·Telegram 호출을 검증하지 않습니다. 야간 경계(22시 포함, 08시 제외), 당일/자정 횡단 구간, 확인 토큰 변경·만료, 잘못된 boolean, 모델 오류 시 미실행을 포함합니다.
